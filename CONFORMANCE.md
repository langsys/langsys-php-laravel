**The profile is the spec's.** Its per-SDK table names `langsys-php-laravel` with the profiles `server, binding`, bound over langsys-php-sdk, and rules for `all` bind every SDK.

Every rule id in the spec is rowed exactly once, including the ones that do not bind this package. A row graded `implemented` names a test that fails when the behaviour is removed; the mutation that proves it is in *Mutation record*. `delegated` names the core row it rests on and the absence probe that shows this package does not do the work itself, with a firing control that shows the probe can fail. `contract` rows are proven against the shared contract fixture, vendored in `tests/contract-fixture/` from langsys-js-typescript at tree `d7f89b89` and run by `tests/Contract/`. Counts live only in *Computed summary*, which is produced by a script, not typed.

**A `delegated` row is only as good as the core row it cites, and it is graded that way.** Its tier is `-`, because the behaviour's tier lives on the core row, and the summary resolves each delegated row against the core's current grade, as the fleet checker does. At `34cc23f` no core row this package delegates to is `not implemented` or `provisional`, and the summary says so only while the core's file grades the blob this file grades.

Test paths are under `tests/`. In an evidence cell, `::name` continues the last file named in that cell. `M`, `T`, `F`, `P`, `L`, `C`, `V`, `S`, `K`, `R`, `A`, `E`, `N`, `B`, `G`, `W`, `X`, `Z`, `D`, `Q`, `Y` and `U` numbers refer to *Mutation record*.

## What surfaced while writing this

Found by executing code against the rules — a probe, a real-core test, a contract test or a mutant.

- **Laravel's `setLocale()` rewrites `app.locale`.** So "the locale is still `app.locale`" cannot tell whether the application resolved the locale. SRV-6's "nothing resolved it" is Laravel's `LocaleUpdated` event having fired this request, which also counts an application that sets its default explicitly.
- **A line `@lang` prints is looked up tokenized, so sync has to register it that way.** `@lang` and `@t` print through `getHtml()` (FRM-8), so `Read our <a href="/terms">terms</a> today` is looked up as `Read our {m0o}terms{m0c} today`. `langsys:sync` compiles views for reading with the app's own compiler, so `@lang` and `@t` compile as the page compiles them, and the core's scanner reads `getHtml()` as a rich line; a scan with Laravel's stock `@lang` would register the raw HTML, which the page never reads. The value marker is left out of the scan, so it never logs its render-time warnings.
- **Compiled Blade lines are not the view's.** Blade drops comments and rewrites directives, so `langsys:sync` gives each hit the line of its own call in the view: the n-th call of a function in the compiled view is its n-th in the source.
- **`Password` implements Laravel's `Rule` contract but has no message before it fails.** A rule object whose `message()` is empty ahead of time is reported, not silently dropped.
- **laravel-data resolves an optional nested object's rules only when the payload carries it.** The listing builds a sample payload from the DTO's own properties.
- **Laravel has no hook before a `Mailable` renders, and a cancelled notification fires nothing after `NotificationSending`.** A `NotificationSending` listener that returns `false` cancels the send, and neither `NotificationSent` nor `NotificationFailed` follows, so a count kept from those events never comes back down. Mail and notifications are both recognised from the call stack while they render (FRM-4).
- **Laravel keeps a compiled view until its template changes, whatever the configuration.** A view compiled with `langsys.enabled` on is served after it is switched off, and the reverse, so what a view compiles to cannot depend on the switch: `@lang`, `@t` and `@choice` compile to `getHtml()` and `choiceHtml()` either way, Laravel's own translator answers them through a macro, and a marked value decides at render. A view compiled before the package was installed prints `@lang` as Laravel's own until it is recompiled, which `UPGRADING.md` and the install steps cover with `view:clear`.
- **A `>` inside a Blade directive's arguments is not the end of a tag.** `<input @disabled($user->locked) value="{{ $email }}">` holds `->` before the attribute, so reading a tag's end as its first `>` outside quotes put the value marker inside `value`. A directive's arguments and a raw echo are skipped as Blade's, like an echo.
- **Laravel's own `get()` tells the app's missing-key handler of every miss.** A read of Laravel's files made only to probe — the spellings of a locale, whether a key holds a list — would call `Lang::handleMissingKeysUsing()` for lines nothing asked for, so each probe runs with the handler off, as Laravel's own `has()` runs, and the handler hears of a line once, when nothing answered it.
- **A marker at the start of a Markdown line turns it into raw HTML.** CommonMark reads a line opening with `<!--` as an HTML block, so a notification's `{{ $line }}` lost its paragraph and its bold. Mail is read as sent and no reader walks it, so a view rendered for mail marks nothing.
- **Octane serves each request in a clone of the worker's container.** What the request resolves lives in the clone, which the event ending it carries, while what was built at boot — the translator, the event listeners — outlives the request, so a client, a request or the current locale is asked of the current container at each call, never captured when it was built. A client a request builds dies with it, its backoff clock too, so the worker builds the client as it starts (`WorkerStarting`) and every request shares it.
- **A job on a sync-driver connection fires the queue's job events inside whatever dispatched it.** `JobProcessed` after `Bus::dispatchSync()` in a controller is mid-request, so only a job a worker runs ends a unit of work.
- **Blade compiles a component tag before any precompiler reads the template.** A precompiler never sees `<x-textarea>`, only the `@component(…)` … `@endComponentClass` Blade wrote for it, and `@slot(…)` … `@endslot` for a slot, so those directives are where a component's body starts, with no element open.
- **Laravel's `choice()` tells the missing-key handler different things across its versions.** Laravel 11.20 and later pick the fallback locale for a key the request's locale lacks and hand the handler no values; 10.x and 11.0 hand it the request's locale and the call's values. A handled miss runs Laravel's own `get()` or `choice()`, so the handler hears what that Laravel tells it.
- **Blade accepts an echo ending in a semicolon** (`{{ $x; }}`) and drops it; an expression handed on as an argument has to drop it too, or the compiled view does not parse.
- **An app's own page assertions read raw HTML.** `assertSee('Hello Ana')` fails on `Hello <!--ls:name-->Ana<!--/ls-->`, so with no key, as in most test suites, nothing is marked, and `UPGRADING.md` says what to assert with one.
- **A class in app/ can fail to load in a deployed install.** Laravel's documented Telescope setup keeps `TelescopeServiceProvider` in app/ while the package itself is a dev dependency, so under `composer install --no-dev` asking whether the class exists throws. Discovery passes such a class over.

## Gaps, ranked by cost

Ranked by what each gap costs someone running the Laravel stack, not by rule order.

1. **VAR-4 — the Blade emitter waits for its readers' release.** It is built and tested; a page `TranslateResponse` walks registers its values only as placeholders once the emitter ships, and it ships with the PHP and TypeScript readers in one wave.
2. **MSG-5 — Blade-only pages show validation errors as Laravel renders them.** That is the request's language only where the app ships its own validation lines for it; the catalog never translates them there. Entries carry source templates for a client to render, and a page with no JS SDK has no client.

## Release gate

- **This tip needs the 838 core, and the core is untagged.** The code calls `resetRequestState()`, `resolveRequestLocale()`, `resolve()`, `translateRich()`, `markResolved()`, `useMissFallback()`, `planSync()`, the migration mode, the server-message API, the snapshot seam, `require_credentials` and the reference reads, none of which v1.3.1 has, and `^1.3` still resolves to v1.3.1 from Packagist. ## Raised against the spec

Measured here and raised through the Reviewer; not findings against this package.

- **MIG-4 against FRM-1, through `trans_choice()`:** MIG-4's `laravel` row reads a pipe string as a plural only when every segment carries a range prefix, or when both of two segments carry `:count`, and MIG-2 sends `trans_choice()` through that row. Laravel's own `trans_choice()` reads any pipe string by the locale's plural index, so with nothing in the catalog `trans_choice('apple|apples', 3)` returns `apples` in plain Laravel and `apple|apples` here, against FRM-1's "exactly what the framework returns". Raised through the PHP lane for a ruling on the `trans_choice` entry point; the conversion is the core's, and nothing in this package changes for it.
- **SRV-2:** its test calls sequential renders proof of nothing, but in a per-request runtime the interleave cannot occur, and sequential reuse across a boundary is the failure that exists. It is worth asking whether the test wording should admit that.
